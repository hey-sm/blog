# 技术知识库写作

## 核心原则

- 使用中文输出，保持专业、清晰、体系化。
- 只服务用户指定的单一技术主题；不要主动混入其他技术栈。
- 将知识库写成可长期维护的工程文档，而不是零散博客。
- 同时覆盖核心概念、实际开发、工程化、生态工具、最佳实践、常见问题。
- 优先面向真实项目经验，避免只给概念解释。
- 对版本敏感的内容要明确版本范围；无法确认最新版本时，说明需要查证。

## 工作流程

1. 识别用户指定的知识库主题，例如 Vue、React、Next.js、Vite、TypeScript。
2. 明确知识库目标：入门学习、项目实战、团队规范、面试体系、迁移指南、源码理解或综合手册。
3. 如果用户没有给目标，默认生成“从基础到项目实战的系统化开发知识库”。
4. 先给出整体知识地图，再展开目录结构。
5. 编写具体文档时，使用固定知识库结构，保证每篇文章可独立阅读，也能纳入整体体系。
6. 输出前检查是否偏离单一技术主题，是否缺少实战示例、生态覆盖或工程建议。

## 知识库目录模型

为一个技术主题设计知识库时，优先包含这些层级：

- 技术定位：它解决什么问题，适合什么场景，和项目开发的关系。
- 环境与工程化：安装、项目创建、目录组织、构建配置、开发工具。
- 核心语法与概念：该技术必须掌握的基础能力。
- 核心机制：响应式、渲染、路由、编译、运行时、类型系统等主题相关机制。
- 常用 API：按使用场景组织，不要只罗列 API。
- 组件或模块实践：真实项目中如何拆分、封装、复用。
- 状态与数据流：状态管理、请求、缓存、异步流程、错误处理。
- 生态工具：只列该技术主流且常用于生产项目的周边生态。
- UI 与交互：组件库、样式方案、动画、表单、可访问性。
- 测试与质量：单元测试、组件测试、端到端测试、类型检查、Lint。
- 性能优化：加载、渲染、缓存、拆包、懒加载、监控。
- 架构与最佳实践：目录规范、代码组织、团队协作、工程约束。
- 高级专题：源码理解、底层机制、SSR、微前端、插件开发等。
- 常见问题：踩坑、错误原因、排查路径、修复方案。
- 实战项目：按业务场景沉淀案例和可复用模式。

## 单篇文档模板

编写具体文章时，优先使用这个结构：

```md
# 标题

## 知识定位
说明这个主题在该技术体系中的位置，以及为什么需要掌握。

## 核心结论
先给出最重要的判断、规则或使用建议。

## 基础概念
解释必要概念，只保留理解实战所需的内容。

## 使用场景
说明什么时候应该使用，什么时候不应该使用。

## 实战用法
给出真实项目风格的代码示例，并解释关键代码。

## 工程实践
说明在生产项目、团队协作、可维护性方面的推荐写法。

## 常见问题
列出高频错误、原因分析、排查方式和修复建议。

## 进阶理解
补充机制、原理、边界条件或性能影响。

## 相关主题
列出知识库内部应该继续阅读的关联文档。
```

## 输出风格

- 标题层级清晰，避免过深嵌套。
- 先讲结论，再讲细节。
- 示例代码要完整到足以理解上下文。
- 对“最佳实践”要说明适用前提，避免绝对化。
- 对生态工具要说明用途、适用场景、选型理由和注意事项。
- 对初学者友好，但不要牺牲专业准确性。
- 避免营销式表述，保持技术文档口吻。

## 图表与可视化（Mermaid）

当内容涉及流程、结构、关系、时序或层级时，**优先用 Mermaid 代码块作图**，不要只用文字描述。**根据场景自己挑选最贴切的图表类型**，不要一律用流程图：

| 场景 | 推荐类型 |
| --- | --- |
| 流程、步骤、决策分支 | `flowchart` |
| 调用交互、请求/响应、时序 | `sequenceDiagram` |
| 状态、生命周期、可中断/转移 | `stateDiagram-v2` |
| 类、接口、模块/数据结构关系 | `classDiagram` |
| 数据模型、表关系 | `erDiagram` |
| 知识分解、层级、脑图 | `mindmap` |
| 演进、版本史、路线图 | `timeline` |
| 分支与提交流（Git 类主题） | `gitGraph` |
| 构成占比 | `pie` |

原则：

- 选能最贴切表达该信息**结构**的类型；类型选错比没有图更糟。
- 用基础、通用语法，确保在主流渲染器（GitHub、Nextra、VS Code 等）都能正常渲染，不堆砌花哨特性。
- 图要服务理解：标签用中文、配简短文字说明；避免图文重复或单张图过载。

## 生态覆盖规则

当用户要求“完整知识库”“开发指南”“实战手册”时，必须覆盖该技术的主流生态。生态内容要围绕用户指定主题展开。

示例：

- Vue 知识库可覆盖 Vue 3、Vite、Vue Router、Pinia、Nuxt、VueUse、vue-tsc、Volar、Vitest、Vue Test Utils、Element Plus、Naive UI。
- React 知识库可覆盖 React、Hooks、React Router、Next.js、Zustand、Redux Toolkit、TanStack Query、Vite、Testing Library、Vitest。
- Vite 知识库可覆盖开发服务器、插件机制、构建优化、环境变量、库模式、SSR、Rollup 关系、常用插件。

不要因为示例中出现其他技术名，就把它们混入用户没有指定的知识库。只有在“生态工具”或“迁移对比”确实需要时才提及。

## 质量检查

输出前检查：

- 是否始终围绕一个技术主题。
- 是否具有从基础到高级的体系结构。
- 是否包含工程实践和真实项目场景。
- 是否覆盖核心生态，而不是只有基础语法。
- 是否避免把知识库写成零散问答。
- 是否给出了可继续扩展的目录或关联主题。
- 是否有版本风险或最新生态风险需要提醒用户查证。
- 是否在合适的地方用了**类型恰当**的 Mermaid 图来表达流程 / 结构 / 关系，而不是纯文字堆砌。
