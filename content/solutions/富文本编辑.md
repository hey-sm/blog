# 富文本编辑器

**约束**:浏览器端富文本编辑,输出 HTML + JSON 双格式;主推 TipTap(基于 ProseMirror),覆盖单机与多人协同两套形态。
**覆盖**:方案选型 / 文档模型 / 图文混排 / 表格 / 插件扩展 / 粘贴清洗 / 撤销与 IME / 协同(Yjs) / 长文档性能 / SSR。
**依赖**:`@tiptap/react` + `@tiptap/pm` + `@tiptap/starter-kit` + `@tiptap/extension-table*` + `@tiptap/extension-image` + `lowlight`(代码高亮)+ `yjs` + `y-prosemirror` + `y-websocket`(协同)。

---

## 0. 选型先讲清楚

| 方案 | 底层模型 | 生态 | 适用 | 不适用 |
|---|---|---|---|---|
| **TipTap** | ProseMirror(Schema + Transaction) | 一流,官方 + 社区 50+ extension | 95% 业务场景 | 极致定制的块编辑器(Notion 风) |
| Lexical | 自研(Node Tree + 不可变更新) | 新生态,Meta 主导 | 高性能、强 React 集成 | 复杂表格、成熟插件少 |
| Slate.js | 自研(JSON immer-like) | React 中流行 | 简单文档、demo | 生产复杂场景(IME / 嵌套 / 协同 历史坑多) |
| Quill | 自研 Delta(扁平 op) | 老牌 | 简单评论框、留言 | 嵌套结构(表格、嵌套列表)非常痛苦 |
| Editor.js | Block 数组 | 中等 | Notion 风块编辑 | 富文本内联(连续段落混合) |
| wangEditor v5 | 基于 Slate | 中文文档 | 国内简单后台 | 协同、复杂插件 |

**结论**:除非你确知场景在 TipTap 的能力之外,**先选 TipTap**。理解 ProseMirror 模型一次,可以迁移到任何严肃富文本场景(包括手撸引擎)。

**ProseMirror vs 其它的根本差异**:ProseMirror 把"文档树 + Schema 校验 + 不可变 Transaction + 撤销栈 + 选区映射"做成一整套定理化模型。这意味着**所有奇怪的 corner case**(IME 中途插表格、嵌套粘贴、协同重映射光标)都有可证明正确的解,而不是堆 if/else。代价是学习曲线陡。

## 1. ProseMirror 模型(不理解这块,任何插件都写不对)

理解四个对象就够:

```
Schema    定义文档允许哪些 Node / Mark, 以及它们如何嵌套
  ↓
Doc       一棵不可变树,叶子 = text,内部 = block / inline node
  ↓
Selection ($anchor, $head) 两个 ResolvedPos,跨节点也只是两个坐标
  ↓
Transaction 一组对 Doc 的 step,执行后产出新 Doc;同时把 Selection 沿 step 映射到新 Doc 的等价位置
```

记住三件事:

- **位置是数字**。`doc.resolve(pos)` 把一个数字还原成"在树的哪一层、哪个节点的第几个子节点之间"。所有跨节点选区操作都靠它。
- **修改 = Transaction**。`view.dispatch(tr)`。多个 step 合并成一个 tr 就是一次撤销/重做,**这是合并历史的唯一手段**。
- **NodeView 是逃生口**。当 PM 默认渲染搞不定(如要嵌一个 React 组件 / iframe / 复杂 resize),写 NodeView 把这个节点的 DOM 完全接管,但让 PM 仍然管它的内容和选区。

```ts
// 一个最小 schema,理解节点/标记如何声明
const schema = new Schema({
  nodes: {
    doc:       { content: 'block+' },
    paragraph: { group: 'block', content: 'inline*', toDOM: () => ['p', 0] },
    text:      { group: 'inline' },
    image: {
      inline: false, group: 'block', atom: true,
      attrs: { src: {}, alt: { default: '' }, width: { default: null } },
      toDOM: n => ['img', { src: n.attrs.src, alt: n.attrs.alt, width: n.attrs.width }],
      parseDOM: [{ tag: 'img[src]', getAttrs: el => ({ src: (el as HTMLImageElement).src }) }],
    },
  },
  marks: {
    bold: { toDOM: () => ['strong', 0], parseDOM: [{ tag: 'strong' }, { tag: 'b' }] },
  },
})
```

**`atom: true` 是什么**:把 image 当作"原子块",光标不进入其内部、删除时整块走。所有"卡片式插入"(视频、附件、公式)都靠 atom + NodeView。

## 2. TipTap 骨架(SSR + 受控)

```tsx
// components/editor/Editor.tsx
'use client'
import { useEditor, EditorContent } from '@tiptap/react'
import StarterKit from '@tiptap/starter-kit'
import Image from '@tiptap/extension-image'
import Table from '@tiptap/extension-table'
import TableRow from '@tiptap/extension-table-row'
import TableCell from '@tiptap/extension-table-cell'
import TableHeader from '@tiptap/extension-table-header'

export function Editor({ value, onChange }: { value: string; onChange: (html: string) => void }) {
  const editor = useEditor({
    extensions: [
      StarterKit.configure({ history: { depth: 200, newGroupDelay: 500 } }),
      Image.configure({ inline: false, allowBase64: false }),
      Table.configure({ resizable: true, allowTableNodeSelection: true }),
      TableRow, TableCell, TableHeader,
    ],
    content: value,
    immediatelyRender: false,                        // ★ SSR 必须
    editorProps: {
      attributes: { class: 'prose max-w-none focus:outline-none' },
    },
    onUpdate: ({ editor }) => onChange(editor.getHTML()),
  })

  return <EditorContent editor={editor} />
}
```

**`immediatelyRender: false` 是什么**:TipTap 默认在 `useEditor` 同步阶段就生成 DOM,这在 Next.js / SSR 下会导致 hydration mismatch(服务端拿到的 HTML 与客户端首渲不一致)。关掉后改为 effect 内挂载,避免不一致。**忘加这一行 = 控制台一片红的 hydration warning**。

**永远不要在父组件用 `value` 反向受控编辑器**。TipTap 是非受控:`content` 只在 mount 时读一次,之后所有修改通过 transaction 内部驱动。要重置内容请显式 `editor.commands.setContent(...)`。

```tsx
// 受控陷阱:这样写会导致每次输入都 setContent → 光标跳到末尾、撤销栈断裂
<Editor value={state} onChange={setState} />   // ← state 千万别再 setContent 回去
```

## 3. 图文混排

图片是富文本里 90% 的坑来源。

### 3.1 上传节点(占位 + 进度 + 失败回退)

```ts
// extensions/uploadImage.ts —— 一条复合命令
import { Editor } from '@tiptap/core'

export function insertImageWithUpload(editor: Editor, file: File) {
  const id = crypto.randomUUID()
  const placeholder = URL.createObjectURL(file)        // ★ 本地预览不等网络

  editor.chain().focus().insertContent({
    type: 'image',
    attrs: { src: placeholder, 'data-upload-id': id, 'data-status': 'uploading' },
  }).run()

  uploadFile(file).then(remoteUrl => {
    URL.revokeObjectURL(placeholder)
    replaceImageSrc(editor, id, { src: remoteUrl, 'data-status': 'done' })
  }).catch(() => {
    replaceImageSrc(editor, id, { 'data-status': 'failed' })
  })
}

function replaceImageSrc(editor: Editor, id: string, attrs: Record<string, any>) {
  const { state, view } = editor
  let tr = state.tr
  state.doc.descendants((node, pos) => {
    if (node.type.name === 'image' && node.attrs['data-upload-id'] === id) {
      tr = tr.setNodeMarkup(pos, undefined, { ...node.attrs, ...attrs })
      return false
    }
  })
  if (tr.docChanged) view.dispatch(tr.setMeta('addToHistory', false))   // ★ 不进撤销栈
}
```

**`addToHistory: false` 是关键**:用户的"插入图片"是一次操作;上传完成回填 URL **不应该**成为一次新的撤销点,否则按 Ctrl+Z 会先回退到"还在上传中"的状态再回退到"没图片",体验非常诡异。

**`URL.createObjectURL` 必须配 `revokeObjectURL`**:否则图片越多内存越涨。

### 3.2 NodeView 接管 resize 与对齐

默认 `Image` 是个裸 `<img>`,没法拖角缩放、没法切对齐。用 NodeView 接管。

```tsx
// extensions/ResizableImage.tsx
import Image from '@tiptap/extension-image'
import { NodeViewWrapper, NodeViewProps, ReactNodeViewRenderer } from '@tiptap/react'
import { useRef, useState } from 'react'

function ImageView({ node, updateAttributes, selected }: NodeViewProps) {
  const { src, alt, width, align } = node.attrs
  const ref = useRef<HTMLImageElement>(null)
  const [dragging, setDragging] = useState(false)

  function onResizeStart(e: React.PointerEvent) {
    e.preventDefault()
    const startX = e.clientX
    const startW = ref.current!.offsetWidth
    setDragging(true)

    function move(ev: PointerEvent) {
      const next = Math.max(80, startW + (ev.clientX - startX))
      updateAttributes({ width: next })             // ★ 实时写 attrs → 自动入 history(LWW 合并)
    }
    function up() {
      setDragging(false)
      window.removeEventListener('pointermove', move)
      window.removeEventListener('pointerup', up)
    }
    window.addEventListener('pointermove', move)
    window.addEventListener('pointerup', up)
  }

  return (
    <NodeViewWrapper className={`image-wrap align-${align ?? 'center'}`} data-selected={selected}>
      <img ref={ref} src={src} alt={alt} style={{ width: width ?? undefined }} draggable={false} />
      {selected && (
        <span className="resize-handle" onPointerDown={onResizeStart} />
      )}
    </NodeViewWrapper>
  )
}

export const ResizableImage = Image.extend({
  addAttributes() {
    return {
      ...this.parent?.(),
      width: { default: null, parseHTML: el => el.getAttribute('width') },
      align: { default: 'center', parseHTML: el => el.getAttribute('data-align') ?? 'center' },
    }
  },
  addNodeView() {
    return ReactNodeViewRenderer(ImageView)
  },
})
```

**Resize 期间 history 处理**:`updateAttributes` 默认每一帧都入 history,会让一次拖拽产生几百个撤销点。两种处理:

- **简单**:依靠 StarterKit history 的 `newGroupDelay`(500ms 内的连续 attrs 改写合并为一次)。够用。
- **彻底**:拖拽期间所有 tr `setMeta('addToHistory', false)`,松手时单独 dispatch 一次 commit。

**`draggable={false}`**:不加这一行,松手时浏览器会把图片拖到别处(浏览器原生拖拽行为)。

### 3.3 浮动布局(图文环绕)

ProseMirror 模型里**没有浮动**:文档是块流。"图文环绕"是 CSS `float` 的视觉效果,模型上 image 仍是 block。靠 `data-align` 属性 + CSS 渲染:

```css
.image-wrap[data-align="left"]  img { float: left;  margin: 0 1em 1em 0; }
.image-wrap[data-align="right"] img { float: right; margin: 0 0 1em 1em; }
.image-wrap[data-align="center"] { display: flex; justify-content: center; }
```

**坑**:`float` 的图后面如果是一个空段落,光标看起来"飞到图旁边"。处理:工具按钮切换 align 后,确保图片节点后面跟一个非空段落,或在 NodeView 里禁止用户把光标落在图后空段。

### 4.1 启用 + 列宽

```ts
Table.configure({
  resizable: true,                  // 列宽可拖

```

```css
.pm-table { border-collapse: collapse; table-layout: fixed; width: 100%; overflow-x: auto; }
.pm-table td, .pm-table th { border: 1px solid #d1d5db; padding: 6px 10px; position: relative; }
```

**`table-layout: fixed` 必加**:不加的话用户输入超长内容时整个表格的列宽都会被冲乱,resize handle 跟着乱跳。

### 4.2 工具栏命令

```tsx
function TableToolbar({ editor }: { editor: Editor }) {
  if (!editor.isActive('table')) return null
  return (
    <div className="table-toolbar">
      <button onClick={() => editor.chain().focus().addRowBefore().run()}>↑行</button>
      <button onClick={() => editor.chain().focus().addRowAfter().run()}>↓行</button>
      <button onClick={() => editor.chain().focus().addColumnBefore().run()}>←列</button>
      <button onClick={() => editor.chain().focus().addColumnAfter().run()}>→列</button>
      <button onClick={() => editor.chain().focus().mergeCells().run()}>合并</button>
      <button onClick={() => editor.chain().focus().splitCell().run()}>拆分</button>
      <button onClick={() => editor.chain().focus().toggleHeaderRow().run()}>表头行</button>
      <button onClick={() => editor.chain().focus().deleteTable().run()}>删表</button>
    </div>
  )
}
```

**为什么用 `editor.chain().focus().X.run()` 而不是 `editor.X()`**:工具栏按钮点击会让 editor 失焦,链式 `.focus()` 把焦点还回去,否则 `X` 命令找不到 selection 失败。

### 4.3 合并单元格的模型

`mergeCells` 内部是把多个 `<td>` 用 `colspan` / `rowspan` 合并到第一个 cell,其余 cell **从 doc 中删除**。不要试图自己实现"逻辑合并保留隐藏 cell"——PM 的 schema 不允许行内 cell 数量与 rowspan 不一致。

合并后的导航:Tab 键由 `@tiptap/extension-table` 已经处理(下一个 cell,如在末尾自动加行)。

### 4.4 表格里塞图片 / 嵌套表格

默认 schema 允许 cell 内放 paragraph + image。**嵌套表格默认不允许**——大部分场景这是正确的(嵌套表格在 UI 上是地狱)。如确需:

```ts
TableCell.extend({
  content: 'block+',     // 父类是 'block+',这里维持即可
})
```

只要 `block+` 包含 `table`(默认包含)就允许嵌套。但**强烈不建议**开启,改用"卡片块 + 副表"的产品形态。

### 4.5 大表格性能

PM 对单个文档内 1000+ cell 的表格渲染明显变慢。对策:

- 不在编辑器里编辑超大表,改成"上传 Excel + 渲染只读 grid"模式
- 真要编辑大表,用 NodeView 把整张表替换成 `react-data-grid` / `ag-grid`,文档里只存一个 `data-table` block + JSON attrs,编辑器内**不展开**单元格内容

## 5. 插件扩展机制

TipTap 的扩展分三种,对应 ProseMirror 的三层能力:

| 类型 | 对应 PM | 用于 |
|---|---|---|
| `Node` | NodeSpec | 文档树新增节点(块/原子卡片/inline) |
| `Mark` | MarkSpec | 文本上的样式标记(粗体、链接、注释批注) |
| `Extension` | Plugin | 不动 schema,加行为(快捷键、装饰、状态监听) |

### 5.1 自定义 Mark:批注/划线

```ts
import { Mark, mergeAttributes } from '@tiptap/core'

export const Comment = Mark.create({
  name: 'comment',
  addAttributes() {
    return { id: { default: null }, author: { default: '' } }
  },
  parseHTML() {
    return [{ tag: 'span[data-comment-id]' }]
  },
  renderHTML({ HTMLAttributes }) {
    return ['span', mergeAttributes(HTMLAttributes, {
      'data-comment-id': HTMLAttributes.id,
      class: 'pm-comment',
    }), 0]
  },
  addCommands() {
    return {
      addComment: (attrs: { id: string; author: string }) => ({ chain }) =>
        chain().setMark(this.name, attrs).run(),
      removeComment: (id: string) => ({ tr, state }) => {
        state.doc.descendants((node, pos) => {
          node.marks.forEach(m => {
            if (m.type.name === 'comment' && m.attrs.id === id) {
              tr.removeMark(pos, pos + node.nodeSize, m.type)
            }
          })
        })
        return true
      },
    }
  },
})
```

**Mark 与 Node 的判断标准**:它能**与文本同位置共存**吗? 能 → Mark(bold、链接、批注);不能 → Node(图片、表格、分割线)。

### 5.2 自定义原子 Node:公式块

```ts
import { Node, mergeAttributes } from '@tiptap/core'
import { ReactNodeViewRenderer, NodeViewWrapper } from '@tiptap/react'
import katex from 'katex'

const FormulaView = ({ node }: { node: any }) => (
  <NodeViewWrapper as="div" className="formula-block">
    <div dangerouslySetInnerHTML={{ __html: katex.renderToString(node.attrs.latex) }} />
  </NodeViewWrapper>
)

export const Formula = Node.create({
  name: 'formula',
  group: 'block',
  atom: true,                                  // ★ 整体当作不可入光标的原子
  selectable: true,
  addAttributes() { return { latex: { default: '' } } },
  parseHTML() { return [{ tag: 'div[data-formula]' }] },
  renderHTML({ HTMLAttributes }) {
    return ['div', mergeAttributes(HTMLAttributes, { 'data-formula': '' })]
  },
  addNodeView() { return ReactNodeViewRenderer(FormulaView) },
  addCommands() {
    return {
      insertFormula: (latex: string) => ({ commands }) =>
        commands.insertContent({ type: 'formula', attrs: { latex } }),
    }
  },
})
```

**`atom + selectable`**:让公式像图片一样,光标"包不进去",编辑公式靠双击弹出 Modal 编辑 latex。这是处理"非文本内容"的标准模式。

### 5.3 行为型 Extension:斜杠菜单

```ts
import { Extension } from '@tiptap/core'
import { Plugin, PluginKey } from '@tiptap/pm/state'

export const SlashMenu = Extension.create({
  name: 'slashMenu',
  addProseMirrorPlugins() {
    const key = new PluginKey('slashMenu')
    return [new Plugin({
      key,
      props: {
        handleTextInput(view, from, to, text) {
          if (text !== '/') return false
          const $from = view.state.doc.resolve(from)
          // 仅在空段或行首触发
          if ($from.parent.type.name !== 'paragraph' || $from.parentOffset !== 0) return false
          showSlashPopup({ view, pos: from })       // 你的 UI 实现
          return false                              // 仍让 '/' 字符照常插入
        },
      },
    })]
  },
})
```

**`return false`**:`true` 表示拦截,字符不进文档。这里我们想保留 `/` 字符,所以 `false`。

### 5.4 InputRule / PasteRule:Markdown 快速输入

```ts
import { InputRule, Extension } from '@tiptap/core'

// 输入 "**xx** " 自动变粗体
export const MarkdownShortcut = Extension.create({
  name: 'mdShortcut',
  addInputRules() {
    return [
      new InputRule({
        find: /\*\*([^*]+)\*\*$/,
        handler: ({ state, range, match }) => {
          const tr = state.tr.delete(range.from, range.to)
            .insertText(match[1], range.from)
            .addMark(range.from, range.from + match[1].length, state.schema.marks.bold.create())
          return tr
        },
      }),
    ]
  },
})
```

**InputRule 与 PasteRule 的区别**:InputRule 看用户敲入的文本流,PasteRule 看剪贴板内容。粘贴大块 Markdown 时走 PasteRule,逐字敲走 InputRule。

## 6. 粘贴清洗(Word / Excel / 截图)

粘贴是富文本第二大坑(仅次于 IME)。

### 6.1 三种来源,三种策略

| 来源 | 内容 | 策略 |
|---|---|---|
| Word | 大量 `mso-*` 私有样式 + 嵌套 `<p>` + base64 图 | **白名单清洗**:仅保留语义结构,丢全部 style |
| Excel | HTML `<table>` 含合并 + Office 私有属性 | 保留 table,丢 style/class |
| 浏览器选区 | 标准 HTML | 走 schema 默认 parseDOM |
| 截图 / 图片 | `clipboardData.items` 含 file | 拦截,走上传流程 |
| 纯文本 | 仅 plain text | 自动落到当前段 |

### 6.2 清洗插件

```ts
import { Plugin } from '@tiptap/pm/state'
import { Extension } from '@tiptap/core'

const ALLOWED_TAGS = new Set(['P','BR','STRONG','EM','U','S','A','UL','OL','LI','H1','H2','H3','H4','BLOCKQUOTE','CODE','PRE','TABLE','THEAD','TBODY','TR','TD','TH','IMG'])
const ALLOWED_ATTRS = new Set(['href','src','alt','colspan','rowspan'])

function sanitizeHTML(html: string): string {
  const doc = new DOMParser().parseFromString(html, 'text/html')
  walk(doc.body)
  return doc.body.innerHTML

  function walk(el: Element) {
    Array.from(el.children).forEach(child => {
      if (!ALLOWED_TAGS.has(child.tagName)) {
        // 不在白名单 → 用 children 替换自身(保留子内容)
        const frag = document.createDocumentFragment()
        while (child.firstChild) frag.appendChild(child.firstChild)
        child.replaceWith(frag)
        // 因为节点替换了,继续遍历原父元素
        return
      }
      // 清掉非白名单属性
      Array.from(child.attributes).forEach(a => {
        if (!ALLOWED_ATTRS.has(a.name)) child.removeAttribute(a.name)
      })
      walk(child)
    })
  }
}

export const PasteSanitize = Extension.create({
  name: 'pasteSanitize',
  addProseMirrorPlugins() {
    return [new Plugin({
      props: {
        handlePaste(view, event) {
          const items = event.clipboardData?.items
          if (!items) return false

          // 1. 优先处理图片(截图)
          for (const it of Array.from(items)) {
            if (it.type.startsWith('image/')) {
              const file = it.getAsFile()
              if (file) {
                event.preventDefault()
                insertImageWithUpload(/* editor */ view as any, file)
                return true
              }
            }
          }

          // 2. HTML 走清洗
          const html = event.clipboardData?.getData('text/html')
          if (html && /<(p|div|table|h[1-6])\b/i.test(html)) {
            const cleaned = sanitizeHTML(html)
            event.preventDefault()
            const slice = view.state.schema.nodeFromJSON(htmlToPmJSON(cleaned, view.state.schema))
            view.dispatch(view.state.tr.replaceSelectionWith(slice))
            return true
          }
          return false      // 其他交给 PM 默认处理
        },
      },
    })]
  },
})
```

**为什么不全用 DOMPurify**:DOMPurify 防 XSS 是对的,但它**保留所有视觉样式**,Word 粘贴下来会带几百个 `mso-` 样式,在编辑器里渲染出来花花绿绿。富文本场景要的是**语义清洗 + XSS 防护双层**:DOMPurify 解决安全,自己的白名单解决语义。

**Word 列表的特殊坑**:Word 的列表不是 `<ul>/<ol>`,而是一堆 `<p class="MsoListParagraph">` + 私有缩进。清洗时这些会全部退化为普通段落,缩进信息丢失。要保留列表语义需要专门的 detector(读 `mso-list:lN level1` 还原层级),这是个独立的工作量,在通用编辑器里通常**不做**——告诉用户"复制 Word 列表时检查格式即可"。

### 6.3 粘贴大文档卡死

Word 粘贴 100 页文档时,sanitize + PM parse 在主线程跑可能卡几秒。对策:

- 文档长度超阈值(如 > 50KB HTML)时弹确认框
- 真要支持:把 sanitize 搬到 Web Worker,parse 结果回主线程后 dispatch

## 7. 复杂交互(撤销 / IME / 选区 / 拖拽)

### 7.1 撤销重做合并

StarterKit 自带 history,默认行为:

- 同类型连续输入 → 合并(每 500ms 起一个新组,由 `newGroupDelay` 控制)
- attrs 变更 → 各自一组(image resize 拖拽期间会产生大量组)
- 跨 NodeView 内部状态 → 不入 PM history,需要自己处理

**自定义合并**:`tr.setMeta('addToHistory', false)` 排除某个 tr,`view.dispatch(tr.setMeta(history.key, { rebased: true }))` 强制合并到上一组。

**协同场景**:history 默认是 global,A 撤销可能撤掉 B 的编辑。Yjs 的 `UndoManager` 是 per-user 的,后面 §8 讲。

### 7.2 IME(中文/日文输入法)

PM 对 IME 做了大量处理(`compositionstart` / `compositionend`),你不应该再去拦截 input 事件、不应该在 composition 期间 dispatch tr,否则候选词框会跳。

**只需要遵守两个规则**:

1. **不要在 onUpdate 同步 setContent**(回写父组件 → 父组件回 setContent → IME 中断)
2. **自定义插件里看到 composition 状态就跳过**

```ts
new Plugin({
  props: {
    handleTextInput(view, from, to, text) {
      if ((view as any).composing) return false   // IME 期间所有手动拦截让位
      // ...
    },
  },
})
```

`view.composing` 是 PM 内部维护的 composition 状态,直接读即可。

### 7.3 选区与块手柄(Notion 风左侧"⋮⋮")

```ts
import { Plugin } from '@tiptap/pm/state'
import { Decoration, DecorationSet } from '@tiptap/pm/view'

export const BlockHandle = Extension.create({
  name: 'blockHandle',
  addProseMirrorPlugins() {
    return [new Plugin({
      props: {
        decorations(state) {
          const decos: Decoration[] = []
          state.doc.descendants((node, pos) => {
            if (node.isBlock && pos > 0) {
              decos.push(Decoration.widget(pos, () => {
                const el = document.createElement('div')
                el.className = 'block-handle'
                el.contentEditable = 'false'
                el.draggable = true
                el.dataset.pos = String(pos)
                return el
              }, { side: -1 }))
            }
          })
          return DecorationSet.create(state.doc, decos)
        },
        handleDOMEvents: {
          dragstart(view, event) {
            const target = event.target as HTMLElement
            if (!target.classList.contains('block-handle')) return false
            const pos = Number(target.dataset.pos)
            const node = view.state.doc.nodeAt(pos)
            if (!node) return false
            event.dataTransfer!.setData('application/x-pm-block', JSON.stringify({ pos, size: node.nodeSize }))
            return true
          },
          drop(view, event) {
            const data = event.dataTransfer?.getData('application/x-pm-block')
            if (!data) return false
            const { pos, size } = JSON.parse(data)
            const drop = view.posAtCoords({ left: event.clientX, top: event.clientY })?.pos
            if (drop == null) return false
            const tr = view.state.tr
            const node = view.state.doc.nodeAt(pos)!
            // ★ 先删后插(insert pos 在 delete 后会偏移,要用 mapping 处理)
            tr.delete(pos, pos + size)
            const insertAt = tr.mapping.map(drop)
            tr.insert(insertAt, node)
            view.dispatch(tr)
            event.preventDefault()
            return true
          },
        },
      },
    })]
  },
})
```

**`Decoration.widget` 是什么**:在文档中注入一个不影响 schema、不进 doc 的 DOM 节点。是"装饰而非内容"的标准做法。

**`contentEditable = 'false'`**:让 widget 不被光标进入,否则用户能编辑这个手柄的"文本"。

**`tr.mapping.map(drop)`**:删除后位置会前移,这是 PM 把"旧位置→新位置"换算的标准方式。所有"先删后插"的操作都必须用 mapping,否则插入位置错位。

### 7.4 链接编辑气泡(BubbleMenu)

```tsx
import { BubbleMenu } from '@tiptap/react'

<BubbleMenu editor={editor} shouldShow={({ editor }) => editor.isActive('link')}>
  <input
    value={editor.getAttributes('link').href ?? ''}
    onChange={e => editor.chain().focus().extendMarkRange('link')
      .setLink({ href: e.target.value }).run()}
  />
  <button onClick={() => editor.chain().focus().unsetLink().run()}>取消链接</button>
</BubbleMenu>
```

**`extendMarkRange('link')`**:把当前选区扩展到整条 link mark 的范围,这样编辑 URL 时不需要用户精确选中链接文字。

## 8. 协同编辑(Yjs + y-prosemirror)

PM 的"不可变文档 + 可映射 step"天然适配 CRDT,Yjs 是事实标准。

### 8.1 接线

```ts
// extensions/collab.ts
import { Extension } from '@tiptap/core'
import Collaboration from '@tiptap/extension-collaboration'
import CollaborationCursor from '@tiptap/extension-collaboration-cursor'
import * as Y from 'yjs'
import { WebsocketProvider } from 'y-websocket'
import { IndexeddbPersistence } from 'y-indexeddb'

export function buildCollabExtensions(docId: string, user: { name: string; color: string }) {
  const ydoc = new Y.Doc()
  const persistence = new IndexeddbPersistence(`doc-${docId}`, ydoc)        // 离线缓存
  const provider = new WebsocketProvider('wss://collab.example.com', docId, ydoc)
  provider.awareness.setLocalStateField('user', user)

  return {
    ydoc, provider, persistence,
    extensions: [
      Collaboration.configure({ document: ydoc }),
      CollaborationCursor.configure({ provider, user }),
    ],
  }
}
```

**禁用 StarterKit 的 history**:协同必须用 Yjs 自己的 `UndoManager`(per-user 撤销),原版 history 会把别人的编辑也撤销。

```ts
StarterKit.configure({ history: false }),
```

### 8.2 Awareness(光标 + 在线状态)

`y-prosemirror` 已经把 selection → awareness → 别人屏幕上的远端光标这一整套自动处理。你只需要:

```ts
provider.awareness.on('change', () => {
```


### 8.3 离线编辑 + 自动合并

`IndexeddbPersistence` 把 Y.Doc 写到 IDB,再开页面时:

```
打开页面 → 从 IDB 加载 → 立即可见可编辑 → WebSocket 连上 → 自动 sync 增量
```

CRDT 保证离线期间所有改动**最终一致**,无需手动 conflict resolution。

**前提**:数据模型必须全部在 Yjs 里。如果你的批注 / 图片上传状态走"额外的 IndexedDB / localStorage",离线期间就会失同步。**让 Yjs 当唯一的协同数据源**。

### 8.4 协同里图片上传

最棘手的细节:用户 A 插入一张图,上传 3 秒,期间 user B 看到的应该是什么?

- **不能传 blob URL**:A 的 `blob:` 在 B 浏览器里访问不到
- **不能等上传完再插**:UI 卡顿,且 A 离线粘贴会丢
- **正确做法**:插入时立即用 placeholder 占位(灰色框 + loading 图标,attrs 记 `uploadId`),A 本地"虚拟"展示真图,B 看到 placeholder;上传完 A 改 attrs 把 `src` 设为远程 URL → Yjs 同步给 B → B 看到图

```ts
// 改写 §3.1 的 insertImageWithUpload —— 协同版
function insertImageCollab(editor: Editor, file: File) {
  const id = crypto.randomUUID()
  // 本地预览:存到 editor instance 上而非文档,避免广播给别人
  ;(editor as any)._localPreviews = (editor as any)._localPreviews ?? new Map()
  ;(editor as any)._localPreviews.set(id, URL.createObjectURL(file))

  editor.chain().focus().insertContent({
    type: 'image',
    attrs: { src: null, 'data-upload-id': id, 'data-status': 'uploading' },
  }).run()

  uploadFile(file).then(remoteUrl => {
    replaceImageSrc(editor, id, { src: remoteUrl, 'data-status': 'done' })
    URL.revokeObjectURL((editor as any)._localPreviews.get(id))
    ;(editor as any)._localPreviews.delete(id)
  })
}
```

Image NodeView 渲染时:

```tsx
function ImageView({ node, editor }) {
  const id = node.attrs['data-upload-id']
  const preview = id ? (editor as any)._localPreviews?.get(id) : null
  const src = node.attrs.src ?? preview                  // 远程 URL → 本地预览 → 否则 placeholder
  if (!src) return <Placeholder status={node.attrs['data-status']} />
  return <img src={src} />
}
```

## 9. 长文档性能

PM 默认渲染整棵文档树,1 万行段落开始变慢,3 万行卡。

### 9.1 标准对策

- **`max-width` + CSS containment**:每个 block 加 `contain: layout style paint`,样式变更不会重排上下文
- **不在 `onUpdate` 跑昂贵操作**:`onUpdate` 每次 keypress 都触发,getHTML 全量序列化超慢;改为 debounce 1000ms
- **不每次都 getHTML**:协同场景内容应该从 Y.Doc 而非 `editor.getHTML()` 拿;持久化场景 onBlur 时序列化即可

```ts
const debouncedSave = useMemo(() => debounce((html: string) => save(html), 1000), [])

useEditor({
  // ...
  onUpdate: ({ editor }) => debouncedSave(editor.getHTML()),
})
```

### 9.2 虚拟滚动(实验性)

PM 的 contentEditable 模型不允许真正的虚拟滚动(光标必须能进入未渲染区域),但有一个折中:把"远离视口的图片/视频/嵌入"换成 placeholder。靠 `Decoration` 在 NodeView 里实现"懒加载":

```tsx
function ImageView({ node, getPos, editor }) {
  const [inView, setInView] = useState(false)
  const ref = useRef<HTMLDivElement>(null)
  useEffect(() => {
    const io = new IntersectionObserver(es => setInView(es[0].isIntersecting), { rootMargin: '500px' })
    if (ref.current) io.observe(ref.current)
    return () => io.disconnect()
  }, [])
  return (
    <NodeViewWrapper ref={ref}>
      {inView ? <img src={node.attrs.src} /> : <div style={{ height: 200, background: '#eee' }} />}
    </NodeViewWrapper>
  )
}
```

文字本身不能懒——10 万字段都进 DOM。真要支持就别用富文本,改成"章节列表 + 单章编辑器"产品形态。

## 10. 输出与回填

| 格式 | API | 用途 |
|---|---|---|
| HTML | `editor.getHTML()` | 渲染、邮件、导出 |
| JSON | `editor.getJSON()` | **存数据库的首选**,无歧义、解析快 |
| 纯文本 | `editor.getText()` | 全文检索、摘要 |
| Markdown | 需 `tiptap-markdown` 扩展 | 跨系统导入导出 |

**为什么存 JSON 而非 HTML**:HTML 解析回 PM doc 时会有歧义(同一段 HTML 可能对应多种 doc 树),且粘贴清洗规则一改老数据可能就解析不出原样。JSON 与 PM 内部模型 1:1,永远稳定。

```ts
// 服务端 ↔ 客户端约定
type SavedDoc = {
  version: number          // ★ schema 版本号,改 schema 时迁移
  json: any                // editor.getJSON()
  html: string             // 用于只读展示,不参与回填
}

// 回填
editor.commands.setContent(saved.json)
```

**版本号必要性**:你加了 `Formula` 节点,旧文档没有,这没关系。但你把 `image` 的 `width` attr 改名 `imageWidth`,老 JSON 就 parse 失败。版本号让迁移函数知道何时跑。

## 11. SSR 渲染只读视图

阅读页(SEO 友好、首屏快)不需要 editor 实例,直接渲染 HTML 即可。但要复用编辑器的 schema 来确保**渲染规则与编辑规则一致**:

```ts
// lib/editor/renderer.ts —— 服务端
import { generateHTML } from '@tiptap/html'
import { extensions } from './extensions'           // 与编辑器共用的扩展列表

export function renderDocToHTML(json: any) {
  return generateHTML(json, extensions)
}
```

```tsx
// app/posts/[id]/page.tsx
export default async function Page({ params }: { params: { id: string } }) {
  const doc = await getDoc(params.id)
  const html = renderDocToHTML(doc.json)
  return <article className="prose" dangerouslySetInnerHTML={{ __html: html }} />
}
```

**为什么不用编辑器实例渲染只读**:editor instance 在 SSR 不可用、首屏多 200KB JS;`generateHTML` 是纯函数,Node 端可跑,与客户端编辑结果完全一致。

**XSS 防护**:`dangerouslySetInnerHTML` 之前必须再过一次 DOMPurify,因为用户可能在编辑期间通过开发者工具改 attrs 注入 `<script>`。schema 校验不防这层。

## 12. 速查:症状 → 出处 → 对策

| 症状 | 出处 | 对策位置 |
|---|---|---|
| Next.js hydration mismatch | TipTap 默认同步渲染 | §2 `immediatelyRender: false` |
| 光标每输入一次跳到末尾 | 父组件受控反向 setContent | §2 不要受控 |
| 中文输入候选词框抖 | 自定义插件在 composition 期 dispatch | §7.2 跳过 `view.composing` |
| 图片上传完撤销栈混乱 | 回填 src 入了 history | §3.1 `addToHistory: false` |
| Resize 拖拽产生几百个撤销点 | 每帧 updateAttributes 一组 | §3.2 `newGroupDelay` 或手动合并 |
| Word 粘贴一片紫色 | 默认走 PM parseDOM,保留 `style` | §6.2 白名单清洗 |
| Word 列表退化为段落 | sanitize 丢了 mso-list 信息 | §6.2 通常不修,告知用户 |
| 协同里 A 撤销撤掉了 B 的修改 | StarterKit 的 history | §8.1 关掉,用 Yjs UndoManager |
| 协同对端看不到本地图片 | 用了 blob URL | §8.4 placeholder + 远程 URL 回填 |
| 长文输入后越来越卡 | onUpdate 全量 getHTML | §9.1 debounce |
| getHTML 与渲染页结果不一致 | 编辑器和阅读页用了不同 schema | §11 共用 extensions 列表 |
| 表格列宽乱跳 | 没设 `table-layout: fixed` | §4.1 |
| 嵌套表格做不出 | TableCell content 默认排除 table | §4.4 一般不建议开 |
| 上线后老文档打不开 | schema 改了字段名 | §10 版本号 + 迁移 |
| 阅读页 SSR 仍要 200KB | 误用 editor 实例渲染只读 | §11 `generateHTML` |

## 13. 不建议自己造的轮子

| 想法 | 建议 |
|---|---|
| 自研富文本引擎(从 contentEditable 起步) | 不建议。光 IME / Selection / Range / undo 就要 2-3 人年 |
| 不用 Yjs 自研协同(WS broadcast diff) | 不建议。最终一致性、撤销栈、离线、光标映射极其复杂 |
| 自研 Word 粘贴解析器(完整保留格式) | 部分场景值得(法律/医疗文档),通用编辑器不值得 |
| 自研 Markdown 双向转换 | 用 `tiptap-markdown` 起步,有边界再补丁,不要从零写 |
| 自研表格编辑(rowspan / colspan) | 用 `@tiptap/extension-table`,不行就 NodeView 嵌 ag-grid |

**判断标准**:这件事在开源生态有 1k+ star 项目吗? 有 → 用它;它对你的场景缺什么 → 写 extension 补;实在不行 → 用 NodeView 把那块完全接管,但仍跑在 PM/TipTap 框架内。从零造引擎几乎总是错误决策。
